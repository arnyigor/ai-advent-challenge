# День 8. Работа с токенами

**Видео-демо:** [day08-demo.mp4 на Яндекс.Диске](https://yadi.sk/i/_zVvrBIFExE_MQ)

Расширение агента [Дня 7](../day07-context-memory) метриками токенов: сколько
токенов у нового сообщения, у всей сохранённой истории, у полного запроса к
провайдеру, и что происходит, когда история реально превышает контекстное
окно модели. Полный план разработки и обоснование решений — в
[DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md).

## Запуск

```bash
pip install -r requirements.txt
python web_server.py            # веб-чат на http://localhost:8008
python day08_agent.py           # CLI с той же логикой
python -m pytest ../tests/test_day8_token_usage.py -q
python run_scenarios.py         # реальные сценарии A/B/C (см. ниже; тратит платные токены)
```

Нужны переменные окружения хотя бы одного провайдера (`DEEPSEEK_API_KEY`,
`GEMINI_API_KEY`, `WORMSOFT_API_KEY` + `WORMSOFT_BASE_URL`, `ROUTERAI_API_KEY`
или `HF_TOKEN`). История и журнал измерений хранятся в `chat_history.db`
(веб/CLI) отдельно от `scenarios.db` (сценарный runner) — обе игнорируются git.

## Что считается токеном

| Метрика | Смысл |
| --- | --- |
| `current_message_tokens` | Только новое сообщение пользователя |
| `history_tokens_before` | Вся сохранённая история до текущего запроса (без system prompt) |
| `request_tokens_before_send` | Весь фактический вход: system + история + новое сообщение, в оформлении адаптера |
| `usage.input/output/total_tokens` | То, что реально насчитал провайдер (API usage) |
| `history_tokens_after` | История после добавления успешной пары user/assistant |
| `session_usage` | Сумма usage успешных вызовов сессии, с флагом `reported`/`complete` |

Предварительные счётчики (`current_message_tokens`, `history_tokens_before`,
`request_tokens_before_send`) — локальная оценка (`token_metrics.py`,
`unicode-segment-estimate-v1`), не настоящий токенизатор провайдера. В UI и
CLI они помечены `≈`. Как только приходит usage от API — это единственное
число, которому можно доверять; локальная оценка и API-usage никогда не
складываются друг с другом. Полная история (`_trim_to_context()` из Дня 7
здесь не используется) — Day 8 всегда отправляет **всё**, что сохранено в
сессии, поэтому переполнение реально достижимо.

## Выбор модели

Все три сценария выполнены на одной модели — **DeepSeek `deepseek-v4-flash`**,
контекстное окно **1 000 000 токенов** (источники и обоснование — в
[model_config.json](model_config.json)). Путь к этому выбору был не прямым и
сам по себе показателен для темы задания:

1. **HuggingFace Router, Qwen2.5-Coder-7B-Instruct (окно 32 768 токенов).**
   Выбран первым — маленькое окно значит, что переполнить его можно одним
   запросом, а не мегабайтами трафика. Сценарий A прошёл полностью, сценарий B
   — 7 из 12 ходов, после чего HF ответил `HTTP 402: You have depleted your
   monthly included credits` — обычная квота бесплатного тарифа, не связанная
   с контекстом. Дальше HF был недоступен независимо от размера запроса.
2. **Wormsoft, Qwen3.8-27B (нативное окно ≈256K–1M).** Прямой запрос с
   ~60 000 токенами не получил отказа за отведённые 60 секунд — истёк таймаут
   HTTP-клиента (`ReadTimeout`), а не контекстная ошибка. Таймаут — не
   доказательство переполнения; от этого варианта отказались.
3. **DeepSeek `deepseek-v4-flash`.** Проверка показала, что реальный запрос на
   289 047 токенов input обрабатывается за 13.6 секунды — быстрее, чем таймаут
   клиента, несмотря на окно в 1 000 000 токенов. Это сделало настоящее
   переполнение достижимым за несколько последовательных вызовов вместо одного
   мегабайтного запроса.

Вход растёт почти линейно по ходам (история заново уходит в каждый запрос),

проекта» в начале и в конце стоил 194 и 6 019 токенов запроса соответственно
— сам вопрос не изменился, изменилось только то, что к нему приложено.
Модель по-прежнему правильно вспомнила «Маяк-17» после 10 промежуточных
блоков.

### C. Переполнение контекста

| Ход | Что произошло | Вход (оценка/факт) | Статус |
| --- | --- | ---: | --- |
| 1–2 | Факт + короткое подтверждение | 148 / 189 (оценка) | `ok` |
| 3 | Стена из 999 999 символов `!` | оценка 1 000 211 | `local_context_limit` — **запрос не отправлен** |
| 4–6 | 3 хода по ~140 000 разнородных слов, история растёт | факт: 269 443 / 539 295 / 808 392 токенов API | `ok` |
| 7 | Ещё один блок поверх истории в 808 392 токена | факт: не отправлен | `provider_context_limit` — **реальный отказ DeepSeek** |
| 8 | `reset()` сессии + короткое приветствие | 141 (оценка) | `ok` |

Два разных механизма отказа, и оба настоящие:

- **Локальная проверка** сработала на ходе 3: локальная оценка (`unicode-
  segment-estimate-v1`) для стены символов дала 999 999 токенов — по одному
  токену на каждый `!`. Оценка сразу превысила окно (1 000 211 > 1 000 000),
  запрос к API не ушёл — `AgentContextLimitError` с причиной
  `local_context_limit`.
- **Реальный отказ провайдера** случился на ходе 7, хотя локальная оценка
  запроса (746 599) в этот момент была ещё далеко от лимита. Причина —
  расхождение оценщика с настоящим токенизатором DeepSeek: на разнородном
  кириллическом тексте реальный счётчик показывает примерно в 1.45 раза
  больше токенов, чем локальная оценка (проверено отдельно: блок в 150 000
  слов — 199 726 по оценке, 289 047 по факту usage). История из ходов 4–6 к
  седьмому ходу реально весила около 808 000+ токенов, новый блок добавлял ещё
  ~270 000 — вместе выше настоящего окна в 1 000 000, и DeepSeek отклонил
  запрос кодом контекстной ошибки. Локальная проверка эту помочь не могла: она
  однозначно недооценивает кириллический текст.
- После `reset()` короткое приветствие снова получило обычный `ok`-ответ —
  агент восстанавливает работоспособность, история испорченной сессии не
  сохранилась (неуспешный ход 7 не попал в БД как пара сообщений).

Этот разрыв между локальной оценкой и настоящим токенизатором — не баг, а
именно то, ради чего в интерфейсе оценки помечены `≈` и никогда не выдаются
за usage провайдера (см. [DEVELOPMENT_PLAN.md, раздел 3](DEVELOPMENT_PLAN.md)).

## Известные ограничения

- Локальный счётчик токенов — эвристика по границам слов/сегментов
  (`token_metrics.py`), не настоящий BPE-токенизатор DeepSeek/HF. Он всегда
  используется только для приблизительной прикидки до отправки и для
  локальной проверки бюджета — не для итоговой статистики.
- Стоимость в README/UI не считается: задание требует именно токены, тарифы
  DeepSeek приведены в `model_config.json` как справочные, не встроены в
  агента.
