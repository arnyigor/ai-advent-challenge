# Day 8 — сценарий видео (`ChallengeVideos/day08-demo.mp4`)

Реализовано в [record-video.mjs](record-video.mjs) (headless Chrome + CDP
скриншоты + ffmpeg, техника из Day 7). Все ответы в видео настоящие — ни один
ответ модели не подставляется заранее, запись останавливается с ошибкой, если
ответ не пришёл (`requireAnswer`/`requireError`).

Провайдер зафиксирован на DeepSeek `deepseek-v4-flash` (окно 1 000 000
токенов) — выбор и его причина объяснены в [README.md](README.md).

## Сцены

| 1 | Интро | Открыть чат, выбрать провайдера DeepSeek в панели | Что за метрики на экране: новое сообщение, история, вход API, ответ API, контекст/лимит |
| 2 | A. Короткий диалог | Отправить факт «Маяк-17», затем вопрос об этом факте | Разница между «новое сообщение» (пара слов) и «вход API» (с историей и system prompt) |
| 3 | Очистка контекста | Кнопка «Очистить контекст» | Сессия и счётчики обнулены перед следующим сценарием |
| 4 | B. Длинный диалог | Факт + 5 нейтральных пронумерованных блоков (реальные ответы, первые 2 — в реальном времени, остальные — подряд без пауз) + повтор того же вопроса о факте | Один и тот же короткий вопрос стоит на входе на порядок больше токенов, потому что история отправляется заново целиком; таблица и график растут по ходам |
| 5 | Очистка контекста | Кнопка «Очистить контекст» | Новая, чистая сессия для эксперимента с переполнением |

| 7.5 | Очистка контекста | Кнопка «Очистить контекст», затем факт + короткое подтверждение заново | Успешная стена из шага 7 осталась бы в истории с локальной оценкой ≈999 999 (хотя реально это лишь ~125 000 токенов) и сразу заблокировала бы следующий ход локально — новая чистая история нужна, чтобы показать именно настоящий отказ провайдера, а не повторный локальный |
| 8 | C.3 Реальное переполнение | Снять чекбокс. Отправить 3 больших смысловых блока (~140 000 разных слов каждый — реальный расход растёт на ~270 000 токенов за ход); первый — в реальном времени с ожиданием, следующие два — подряд | История реально растёт до сотен тысяч токенов за настоящие деньги и время — не только по счётчику |

## Реальные числа, которые ожидаются на записи

Взяты из уже проведённого прогона `run_scenarios.py`
([results/scenarios.json](results/scenarios.json)) и точечных проверок при
подготовке сценария; сама запись может немного отличаться (другая генерация
токенов у той же модели), но порядок величин и статусы должны совпасть:

- Короткий вопрос без истории — вход API около 150–200 токенов.
- Тот же вопрос после длинной истории — вход API в разы больше при том же
  тексте вопроса.
- Стена из 999 999 символов `!` — локальная оценка тоже около 999 999,
  запрос блокируется локально.
- Та же стена с включённым force — реальный usage около 125 000 входных
  токенов, ответ приходит успешно (проверено отдельно: 125 189 токенов, 7.5 с).
- Три блока по 140 000 слов — реальный вход на третьем ходе около 800 000
  токенов (проверено: 269 443 → 539 295 → 808 392); четвёртый блок поверх
  этой истории получает `provider_context_limit` (проверено на реальном
  вызове).
