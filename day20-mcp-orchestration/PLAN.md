# День 20: план и контракт

1. Зарегистрировать три отдельных MCP stdio-сервера в `servers.json`: knowledge, analysis, storage.
2. Получить от каждого `initialize` и `tools/list`; построить общий каталог с полными именами `server.tool`.
3. Передать модели Gemini 3.5 Flash этот каталог как function declarations. Модель выбирает имя и аргументы одного инструмента; клиент проверяет схему и направляет `tools/call` в соответствующую MCP-сессию.
4. Вернуть ответ инструмента модели вместе с исходной частью ответа модели и подписью рассуждения. Повторять, пока модель не выдаст финальный ответ; максимум 16 вызовов.
5. Не допускать записи до `analysis.verify=true` и проверять содержимое файла через `storage.read`. Показывать имя модели, число её ходов и трассу MCP в UI.
6. Проверить реальный запуск Gemini, автоматические интеграционные сценарии с моделью-имитатором и записать видео живого запуска.

## Контракты

- knowledge.search(query) → ids; knowledge.read(id) → документ.
- analysis.summarize(items) → {summary,source_ids}; analysis.verify(items,summary,source_ids) → {valid}.
- storage.save(content) → {id,path}; storage.read(id) → {content,path}.
- `knowledge.read` и `storage.read` имеют одинаковое локальное имя, поэтому модель видит полные имена, а маршрутизатор использует разные сессии.
- Корпус импортируется из дня 19; сервер хранения принимает только сгенерированные ID.
