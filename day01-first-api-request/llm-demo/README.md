## 🧩 Слайд 3 — Семь источников LLM

| Бэкенд | Тип | Как включается |
|---|---|---|
| **llama.cpp** | локальный | сервер на `127.0.0.1:8080` (OpenAI-совместимый API) |
| **Ollama** | локальный | `ollama serve` на `127.0.0.1:11434` |
| **DeepSeek** | облако | `DEEPSEEK_API_KEY` в окружении |
| **OpenAI** | облако | `OPENAI_API_KEY` в окружении |
| **RouterAI** | облако | `ROUTERAI_API_KEY` в окружении (модель `qwen/qwen3.8-27b`, `https://routerai.ru/api/v1/chat/completions`) |
| **Gemini** | облако | `GEMINI_API_KEY` в окружении |
| **Mock** | встроенный | **всегда работает**, без сети — гарантированный fallback |

Детект автоматический: сервер при открытии страницы проверяет каждый бэкенд и показывает индикатор.
**Если ничего нет — Mock отвечает**, чтобы демо продолжало работать на любой машине.

### Переменные окружения (все опциональны)

```bash
DEEPSEEK_API_KEY=sk-...     # DeepSeek
OPENAI_API_KEY=sk-...       # OpenAI
ROUTERAI_API_KEY=...        # RouterAI (https://routerai.ru)
GEMINI_API_KEY=AIza...      # Gemini
LLAMACPP_URL=http://127.0.0.1:8080   # свой адрес llama.cpp
OLLAMA_URL=http://127.0.0.1:11434    # свой адрес Ollama
PORT=3000                   # порт Web-сервера
```

Где взять ключи и как задать их в PowerShell — в `tools/API_KEYS.md`.

## 🏗 Слайд 4 — Как это устроено (3 слоя)

```
Браузер (index.html)          Сервер (server.mjs)              LLM
─────────────────────         ──────────────────               ───
чат, чипы бэкендов   ──SSE──▶  /api/chat  ──fetch──▶  llama.cpp /v1/chat/completions
стриминг по токенам           /api/backends (детект)  Ollama /api/chat
                              fallback-цепочка Gemini  DeepSeek / OpenAI (OpenAI-совместимые)
                                              Gemini streamGenerateContent?alt=sse
```

- `server.mjs` — обычный `node:http`, **без единого npm-пакета**.
- Ответ уходит браузеру **SSE-стримом**: `data: {"type":"token","text":"…"}` … `data: {"type":"done",…}`.
- Браузер читает SSE через `fetch` + `ReadableStream` и печатает токены на лету.
- Gemini: если модель недоступна (404/503), сервер сам идёт по **fallback-цепочке** моделей (`3.5-flash-lite → 3.5 → 3.6 → 3.7 → 2.5-flash`).
- Ключи API не покидают сервер — браузер ходит только в локальный прокси.

## 🧪 Слайд 5 — Сценарии проверки (для любого чекера)

1. **Есть локальная LLM** (llama.cpp/Ollama) → запустить её → `run.bat` → выбрать локальный бэкенд → ответ печатается по токенам.
2. **Есть API-ключ** → задать `DEEPSEEK_API_KEY` / `OPENAI_API_KEY` / `GEMINI_API_KEY` → выбрать облачный бэкенд.
3. **Нет ничего** → `run.bat` → **Mock** → демо работает и объясняет, как подключить настоящую LLM.

### Самодиагностика Gemini

```powershell
powershell -ExecutionPolicy Bypass -File ../../tools/check-gemini.ps1
```

Ключ берётся из `$env:GEMINI_API_KEY` (без хардкода). Скрипт показывает список моделей, доступных ключу, решает логическую задачу (зависимости задач с противоречием) с fallback по цепочке и печатает ответ + расход токенов.

> Файл с UTF-8 BOM — иначе PowerShell 5.1 ломает кириллицу при парсинге.
