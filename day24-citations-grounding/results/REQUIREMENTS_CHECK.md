# Проверка соответствия заданию — День 24

Проверен реальный отчёт `grounding.json` после изменения контракта и гибридного поиска.
Контрольный набор сохранён: те же 10 вопросов Дней 22 и 23, без замены неудобного вопроса.

| Пункт задания | Реализация | Результат |
|---|---|---|
| Модель возвращает ответ | Обязательный `answer` в исходном JSON модели; проверяется совпадение с подтверждёнными claims | 10/10 |
| Модель возвращает список источников | Обязательный `sources`: `source`, `section`, `chunk_id`; метаданные сверяются с индексом | 10/10 |
| Модель возвращает цитаты | Обязательный `quotes`; все цитаты дословно входят в найденные чанки и связаны с утверждениями | 10/10 |
| Проверить наличие источников на 10 вопросах | `checks.has_sources`, отдельно проверяются метаданные | 10/10 |
| Проверить наличие цитат на 10 вопросах | `checks.has_quotes`, отдельно проверяется дословность | 10/10 |
| Совпадает ли смысл с цитатами | Отдельный вызов LLM проверяет каждое утверждение по его цитатам; обоснования сохранены | 10/10 по оценке модели |
| При релевантности ниже порога — «не знаю» и уточнение | Если ни один кандидат не прошёл cosine 0.83, генерация ответа пропускается | Реальный отрицательный вопрос: max cosine 0.813 < 0.830, prompt_chars=0, отказ + уточнение |

Дополнительно проверен вопрос о пароле Atlas: источники о проекте найдены, но самого
пароля в них нет. Система также отказывается отвечать и просит уточнение.

Каждый результат, включая отказ, содержит поля answer / sources / quotes.
У отказа sources и quotes пустые: обязательность структуры не означает выдумывание доказательств.
У десяти контрольных вопросов все источники и цитаты непустые.

Что было исправлено относительно первой версии:

- Модель сама возвращает три обязательных поля; сервер проверяет их вместо создания
  отсутствующих полей из ответа с claims.
- В UI три самостоятельных блока, нумерация У/И/Ц и связанная подсветка.
- Сохранили cosine-порог и reranker Дня 23; добавили FTS5 для точных слов в коде.
  Pool — объединение top-8 vector и top-8 lexical, максимум 16 уникальных кандидатов.
  Каждому lexical-кандидату вычисляется настоящий cosine; он тоже проходит threshold.
- Таблица показывает три проверки отдельно для каждой из 10 строк.
- Видео направляет внимание на конкретный блок, а не просто показывает статичный интерфейс.

Ограничение оценки: соответствие смысла проверяет LLM, а не человек. Дословность,
принадлежность чанку, корректность метаданных и обязательные поля проверяются кодом.
Оценка цитирования не приравнивается к полноте ответа или истинности источника.
