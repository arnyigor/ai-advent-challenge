# Доказательства дня 30

Файлы созданы `verify.py` против работающего сервиса: Qwen3-1.7B Q4_K_M на CPU
(окно 4096, 1 слот, `--reasoning off`), llama.cpp build 11054, шлюз
`http://192.168.1.212:8091`, модель `http://127.0.0.1:8081` с `--api-key`.

| Файл | Что внутри |
|---|---|
| `day30-backend.json` | профиль backend: alias, `n_ctx=4096`, `total_slots=1`, совпадение счёта токенов (`83 = 83`), 401 при прямом вызове без ключа модели |
| `day30-core.json` | контракт через шлюз: 401/400/413, неизвестная модель, запрет клиентского `system`, `temperature`, `stream`; пара «история / без истории» (КЕДР-42) |
| `day30-budget.json` | `max_tokens=1` принимается, `finish_reason=length` при обрезании |
| `day30-context.json` | граница окна по реальным токенам: 3894+16+32 → 200; 3992+256+32 → 400 `context_limit` за 28 мс |
| `day30-load.json` | 20 последовательных запросов с паузой 6.2 с (окно лимита не нарушено), все 200 |
| `day30-concurrent.json` | 3 клиента × 3 повтора: 9 ответов, каждый со своим маркером |
| `day30-queue.json` | переполнение очереди: 503 `queue_full` + `Retry-After`, затем успешный запрос |
| `day30-ratelimit.json` | 10 запросов прошли, 11-й → 429 `rate_limited` + `Retry-After: 55`, после окна снова 200 |
| `day30-network.json` | шлюз отвечает на адресе bind (health, models, 401 без ключа, генерация) |
| `day30-backend-down.json` | при остановленной модели: `/health` 503 и чат 503 `backend_unavailable` |
| `day30-backend-up.json` | после запуска модели: `/health` 200 и успешный запрос |
| `day30-summary.json` | сводка по стадиям: вызовы, статусы, проваленные ожидания, медианы |
| `day30-chat-ui.json` | живой веб-чат в headless Chrome: вопросы, ответы, строки с временем/токенами/`finish_reason`/`request_id` |
| `chat-00-empty.png`, `chat-01-seed.png`, `chat-02-history.png` | снимки того же чата 1920×1080 (ключ в поле типа password) |
| `access.log` | access-лог шлюза (метаданные без промптов и ответов), вне Git |
| `model-autostart.log`, `gateway.log` | stdout модели и транскрипт шлюза при запуске задачами планировщика, вне Git |

Ключи и пароли в файлы не попадают: `verify.py` пишет только метки ключей
(`main`, `load`, `tests`, …). Фрагменты ответов есть только в `day30-core.json`
(доказательство передачи истории) и обрезаны до 300 символов. Значения ключей из
`keys.json` и `model-key.txt` в `evidence/` не встречаются — проверено поиском.

Отдельно: `day30-chat-ui.json` и `chat-0*.png` сделаны не `verify.py`, а
`capture-chat.mjs` (node + headless Chrome через CDP). Это настоящие ответы работающего
шлюза, полученные браузером; ответы в кадре совпадают с полями `turns` в JSON.

Чего в файлах нет по замыслу: запросов со второго устройства в LAN и применения
правила firewall (нет прав администратора и второго устройства), а также
перезагрузки ОС — см. раздел «Ограничения и непроверенное» в README.
