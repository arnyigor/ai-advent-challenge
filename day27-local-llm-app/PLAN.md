## Рекомендация

Сделать локальное веб-приложение «Редактор текста»: пользователь вставляет текст, выбирает «Сократить», «Переписать понятно» или «Выделить задачи», получает результат, может уточнить его в диалоге, скопировать или сохранить в TXT.

Это самостоятельный полезный сценарий поверх проверенного HTTP-контракта дня 26. Один запрос модели на действие, без RAG и дополнительных моделей. Исходный текст и история сохраняются в пределах открытой вкладки; после перезагрузки пользователь начинает новую работу. Постоянное хранение можно добавить позднее.

| Веб-редактор текста | HTTP-клиент и веб-стенд дня 26 | Свободный ввод, режимы, история, результат, ошибки | Основной вариант: полезно, наглядно, мало зависимостей |
| Чат с RAG и памятью дня 25 | UI, SQLite, цитаты, память, внедрение llm | Адаптер call(), локализация всех вызовов, аудит embeddings, проверка JSON и задержек | Следующее расширение, если нужен ассистент по проекту |
| CLI для обработки текста | Node-клиент дня 26 | Аргументы, stdin/файл, вывод | Самый короткий путь, но менее нагляден в видео |
| Telegram-бот | В исследованных днях не найден готовый бот | Bot API, токен, polling, история, обработка доступа | Не выбирать для первого этапа: требует внешнего транспорта |

Telegram может использовать локальную LLM без облачных моделей, но сообщения идут через Telegram и приложение требует интернета. Это отличается от полностью автономного приложения.

День 25 технически пригоден для замены провайдера: ChatAgent принимает llm и embedder. Однако один ход включает condense, генерацию, смысловую проверку и обновление памяти; возможны дополнительные вызовы. Время одного короткого запроса дня 26 нельзя переносить на полный RAG-ход. SentenceTransformerEmbedder создаёт SentenceTransformer(model_name): без подготовленного локального кеша возможно скачивание. Для автономности нужны локальные веса, запрет сетевой загрузки и соответствие модели/размерности существующему индексу. HashEmbedder из тестов не является равноценной заменой семантических embeddings.

## Архитектура выбранного приложения

Браузер → Node-сервер на 127.0.0.1 → Strata /v1/chat/completions → Node → результат в браузере.

- Node.js 22+, стандартные модули и fetch; отдельная папка дня 27, дни 25–26 не меняются.
- LOCAL_LLM_URL и LOCAL_LLM_MODEL задаются явно. Единственный провайдер — локальный endpoint, облачных клиентов и fallback нет.
- Веб-порт отдельный, например 8789 с возможностью настройки. Сервер слушает loopback.
- UI и шрифты локальные, без CDN, аналитики и внешних ресурсов.
- Клиент Strata принимает system + user + assistant messages, возвращает ответ, время, usage и finish_reason, если они присутствуют.
- История передаётся приложением; сервер инференса не обязан помнить предыдущие запросы.
- Для уточнения отправляются исходный текст, выбранный режим и ограниченная история. При достижении лимита приложение предлагает начать новую работу; исходник не исчезает молча.
- Модель не исполняет код, не читает файлы и не вызывает инструменты. Экспорт — обычный TXT по действию пользователя.

## Этапы реализации

### 1. Контракт и сценарии — без модели

Зафиксировать три режима, формат свободного текстового ответа, максимальные размеры ввода/истории и ожидаемое поведение ошибок. Подготовить нейтральные примеры: длинное объявление, запутанная инструкция, заметка встречи с явными задачами. Не требовать JSON от модели для первой версии.

### 2. Локальный HTTP-клиент — без модели

Перенести проверенные ограничения дня 26 в local-llm.mjs. Добавить messages, system-инструкции режимов, отмену запроса и проверку ответа. Параметры генерации использовать только после проверки поддержки Strata; streaming не нужен для первой версии. При length показать, что ответ обрезан. Если нужна авторизация, ключ хранить на сервере, не отправлять браузеру и не выводить в журнал.

### 3. Сервер — без модели

Реализовать POST /api/transform и POST /api/refine. Валидировать mode, типы сообщений, размер тела и допустимые роли; system-инструкцию строить на сервере. Проверять Host/Origin, отдавать только файлы web/, запрещать обход пути. Ограничить параллельные генерации, при занятости возвращать понятный статус. Таймаут и недоступность Strata показывать как ошибки, без подмены ответа.

### 4. Интерфейс — без модели

Две панели «Исходный текст» и «Результат», выбор режима, кнопка обработки, поле уточнения, копирование, TXT, новая работа. Во время запроса показать ожидание и доступную отмену. Для неуспешной операции сохранить введённый текст и предыдущий успешный результат. Выводить ответ через textContent; текст модели не трактовать как HTML. В деталях показать фактическую модель и время, не перегружая основной экран.

### 5. Офлайн-проверки — без модели

Использовать временный loopback HTTP-сервер: проверить messages и историю, запрет удалённых адресов/редиректов, таймаут/отмену, HTTP/JSON/пустой ответ, обрезанный ответ. Проверить HTTP API, ограничения тела/истории и безопасный вывод HTML-подобного текста. Такие проверки подтверждают приложение, но не качество локальной LLM. Тестовые ответы не выдавать за реальные результаты в UI или видео.

### 6. Реальная интеграция — позднее, после снятия текущего ограничения

Сверить URL/id с работающей Strata. Выполнить каждый режим на подготовленном тексте и одно уточнение. Оценить сохранение чисел/имён/сроков, отсутствие выдуманных задач и следование запросу. Сохранить конкретный отчёт прогона с запросами и ответами без личных данных. Проверить работу без внешней сети: браузер и приложение не используют внешние ресурсы; генерация остаётся доступна через loopback. Сверить запросы с журналом Strata. При необходимости менять инструкции приложения, не настройки модели автоматически.

### 7. Видео и сдача

Сценарий 90–150 секунд: Strata с загруженной моделью → веб-приложение → исходный текст и результат → уточнение → копирование/TXT → подтверждение обработки в Strata. Если ожидание сокращено, подписать это. Проверить читаемость и фактические ответы. Видео: ChallengeVideos/day27-demo.mp4, вне Git; код и README — в папке дня 27. Публикация и отправка результата — отдельный этап.

## Готовность

Пользователь вводит произвольный текст, получает реальный ответ локальной модели и уточняет его с учётом истории. Результат можно скопировать/сохранить. Приложение работает без облачных моделей и внешних ресурсов, показывает реальные ошибки и не переключается на облако. Офлайн-тесты проходят; отдельно выполнен реальный прогон и записано проверенное видео. До этого день 27 не объявляется выполненным.
