## 2. Архитектура и реализация

Браузер → Python HTTP на 127.0.0.1:8793 → локальный E5 на CPU → существующий SQLite → контекст из top-4 → OpenAI-compatible loopback API → ответ + найденные фрагменты.

1. `rag.py`: метаданные индекса, ленивый OfflineEmbedder, проверка имени и размерности, повторное использование search() дня 21. Hugging Face offline flags и local_files_only запрещают скачивание; отсутствие кеша — ошибка. Индекс не перестраивается.
2. LocalModel: только literal loopback HTTP, без proxy и redirects, таймаут 180 секунд, ограничение ответа, temperature 0.1 и max_tokens 700. Параметры требуют реальной проверки на актуальном сервере. Нет облачного fallback, автоматического discovery или запуска сервера модели.
3. Контекст: source/section/номер для каждого фрагмента, до 18 000 символов; top-k ограничен 6. Это символьный бюджет, не точный токеновый: после реального прогона сверить вместимость с контекстным окном модели. Нет удаления фрагментов молча. У модели инструкция отвечать только по контексту и признавать недостаток данных.
4. Веб: отдельная кнопка поиска без генерации, ответ, времена поиска/генерации, фрагменты, предупреждения при length и неверных ссылках. DOM textContent, локальные ресурсы, exact маршруты, Host/Origin, лимит тела, один запрос одновременно. GET config не загружает модели.
5. CLI: inspect только читает индекс; retrieve-only загружает E5, но не вызывает LLM; обычный вопрос выполняет inference.

Поиск пока vector-only, без порога и reranking дня 23. Он всегда возвращает ближайшие фрагменты; для off-topic отказ зависит от модели и нуждается в проверке. UI показывает кандидаты поиска, а не автоматически доказанные утверждения. Номер ссылки проверяется кодом; подтверждение смысла — нет.

## 3. Сравнение качества, скорости, стабильности

`evaluate.py --run`: 13 вопросов недели 6, по 3 повтора, последовательные запросы. Контекст извлекается один раз на вопрос и дословно повторяется для провайдеров; SHA-256 подтверждает одинаковый prompt. System, temperature и бюджет ответа одинаковые, но провайдеры могут различаться в применении параметров. Локальный режим основной; облачный провайдер включается только явным --cloud-model и отправляет найденные документы наружу.

Отчёт сохраняет ответы/контекст, retrieval hit, время первого поиска (включая холодную загрузку), времена генерации, медиану/p95, долю успешных вызовов, обрезанные ответы, наличие/диапазон ссылок и количество разных текстов на одинаковый вопрос. Ошибка одного вызова не прерывает остальные. Повторяемость текста не означает повторяемость правильности. Ошибка подготовки поиска останавливает прогон: сначала исправить локальные зависимости.

Ручная оценка каждого ответа: 0 — выдумка/ошибка/отсутствие полезного ответа при наличии фактов; 1 — частично верно, есть пропуски; 2 — все ключевые факты верны, ссылки подтверждают утверждения. Заполнить manual_quality и notes, отдельно оценить off-topic отказ. Итоговую сравнительную оценку опубликовать в README после проверки, не выдавать технические метрики за качество.
