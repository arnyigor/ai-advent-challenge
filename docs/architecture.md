# Архитектура AI Advent Challenge

## Структура проекта

Это репозиторий ежедневных заданий AI Advent Challenge. Каждый день находится
в отдельной папке `dayNN-slug/` со своим README, исходниками и зависимостями.
Корневой `README.md` описывает запуск ежедневного workflow. `tools/` содержит
общие утилиты, включая `tools/llm/` и скрипты сдачи. `tests/` содержит тесты.
`docs/` — общая документация проекта: архитектура, API помощника и схема данных.
`ChallengeVideos/` — локальные видео; MP4/MOV/MKV исключены из Git.

## Где находятся RAG и MCP

`day21-document-indexing/` — загрузка документов, структурный chunking,
embeddings, SQLite с векторами и FTS5. `day28-local-rag/` — локальный hybrid
retrieval и генерация через LocalModel, совместимый с chat completions API.
`day17-first-mcp-tool/` — пример Git MCP-сервера и клиента через stdio.
`day31-developer-assistant/` — помощник разработчика, объединяющий документацию
проекта и живой Git-контекст. Он переиспользует индексатор дня 21 и RAG дня 28.

## Путь запроса помощника

`/help <вопрос>` → assistant.py проверяет команду и свежесть корпуса → MCP-клиент
запускает project_mcp_server.py через stdio → initialize, tools/list, tools/call
→ get_project_context возвращает ветку и HEAD → поиск top-6 чанков в SQLite
→ документы и Git-контекст передаются выбранной LLM → ответ с источниками [n].
Команда `/help` без вопроса использует вопрос о структуре проекта.
CLI и HTTP UI вызывают один Assistant, поэтому pipeline и дефолты одинаковы.
Генератор выбирается явно: локальный API, Gemini или бесплатный OpenRouter.
Embeddings и чтение Git остаются локальными. Для cloud используется только
выбранный провайдер; при ошибке не происходит скрытого платного fallback.

## Индексация и актуальность

Корпус: корневой README, README папок dayNN-* и Markdown в корневой docs/.
Секреты, `.env`, служебные каталоги, видео и исходники не сканируются.
E5 multilingual-e5-small на CPU кодирует документы с `passage:`, запросы с
`query:`. Используется только локальный кеш модели. Chunking структурный,
1000 символов с перекрытием; поиск гибридный vector + FTS5, максимум 6 фрагментов.
По умолчанию источники ограничены общей docs, корневым README и README дня 31.
Если в вопросе назван `day28` или «дня 28», добавляется README соответствующего
дня. Это защищает от смешивания API разных дней в общем вопросе о помощнике.
Перед вопросом сравнивается SHA-256 текущего корпуса и corpus_hash индекса.
После изменения документов нужно выполнить `assistant.py --index`.

## Границы

Помощник не меняет файлы и Git. MCP читает только название репозитория, ветку и
SHA HEAD; список файлов и diff в дне 31 не реализованы. Состояние ветки читается
при каждом вопросе, оно не хранится в RAG. История чата не передаётся модели.
Документы — данные, а не инструкции. Если фактов нет, модель должна сообщить
«В найденных документах недостаточно данных». Проверка номеров ссылок не
является проверкой истинности текста. Ошибки модели/MCP показываются явно.
