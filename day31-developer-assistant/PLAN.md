# День 31: план реализации и приёмки

## Цель и границы

Ассистент объясняет **этот репозиторий** через `/help <вопрос>`. RAG использует
корневой README, README отдельных дней и настоящую папку `docs/`. Текущая ветка
приходит из Git через отдельный MCP-процесс, а не из документации или памяти LLM.
Без аргументов `/help` объясняет структуру проекта. Интерфейсы: CLI и локальная
веб-страница. Модель — существующий совместимый локальный chat API.

## Последовательность работ

1. Изучить дни 17, 21, 28, правила агента и доступные зависимости.
2. Зафиксировать контракт ниже. Создать `docs/architecture.md`, `docs/api.md`,
   `docs/data-model.md` с проверенными по коду сведениями о репозитории и дне 31.
3. Индексировать разрешённые документы: Markdown → структурные чанки до 1000
   символов → `passage:` embeddings multilingual-e5-small на CPU → SQLite с
   векторами, FTS5, именами источников и SHA-256. Использовать код дня 21.
4. Поиск: `query:` embedding, vector + FTS5, top-6. Использовать пайплайн дня 28;
   каждый запрос проверяет свежесть корпуса. После правки документа нужен reindex.
   Общие вопросы ограничить docs + корневой README + README дня 31; README
   другого дня допускается в ответ, если этот день назван в вопросе.
5. MCP stdio: `initialize` → `tools/list` → `tools/call(get_project_context,{})`.
   Только фиксированные read-only Git-команды; репозиторий задан серверу при запуске.
   detached HEAD возвращается явно вместе с SHA. Никаких команд shell от модели.
6. `/help`: проверка команды → актуальность индекса → MCP → retrieval → prompt
   с документами и живым контекстом → LLM → ответ, источники, трасса, время,
   finish_reason. Ошибки MCP/модели не выдавать за успешный ответ.
7. CLI и браузер используют один сервис и дефолты. UI показывает вопрос, ответ,
   ветку, использованные источники, фрагменты и фактический MCP-каталог/вызов.
8. Проверить контракт тестами, выполнить реальный MCP и реальные вопросы к LLM.
   Отдельно проверить отказ на неизвестный факт, ошибки и устаревший индекс.
9. Записать видео по `DEMO.md`, сверить кадры и декодирование MP4. Видео хранить
   в `ChallengeVideos/`, вне Git. Сохранить результаты запросов и проверок.

## Контракт

```mermaid
flowchart LR
    D[README + docs] --> I[E5 + SQLite]
    Q[/help вопрос] --> A[Assistant]
    A --> M[MCP stdio]
    M --> G[git branch + HEAD]
    G --> P[Prompt]
    A --> I
    I --> P
    P --> L[Локальная LLM]
    L --> R[Ответ + источники + MCP-трасса]
```

- Ввод: строка `/help` или `/help <вопрос>`; другие команды — ошибка.
- MCP: `get_project_context()` → `{repository, branch, head, detached}`.
- Выход: `{question, answer, project, mcp, sources, model, usage,
  finish_reason, citation_ids_valid, has_citations, retrieval_sec, generation_sec}`.
- Источник содержит `source`, `section`, `text`, `rank`, `score` и `chunk_id`.
- HTTP: `GET /api/config`, `POST /api/help {command: string}`; UI на loopback.
- Секреты и скрытые папки не входят в корпус; индексируется явный allowlist.
- Генерируемые `day31-developer-assistant/data/project.sqlite3` и его `.tmp`
  допускается пересоздавать при явном `--index`; исходники не удаляются.
- Ограничения: один запрос за раз, вопрос ≤1000 символов, тело ≤8192 байт,
  контекст ≤18000 символов, таймаут MCP 30 с, генерации 180 с.

## Критерии приёмки

| Требование | Доказательство |
|---|---|
| README + docs в RAG | Статистика индекса и список документов; источники ответа |
| Семантический retrieval | Реальная E5, идентичность/размерность модели в SQLite |
| MCP git branch | Каталог и результат stdio-вызова совпадают с `git branch --show-current` |
| `/help` о структуре | Ответ на русском с конкретными папками и ссылками [n] |
| Документация + живой контекст | В одном результате источники docs и фактическая ветка |
| Нет нужного факта | Ассистент сообщает недостаток данных, не придумывает число |
| Ошибки | Недоступность модели/MCP видна; stale index требует reindex |
| Видео + код | Запускаемые исходники, README, DEMO, MP4 вне Git |

## Основания

SDK MCP 2.2.0 проверен через установленный Python и сигнатуры ClientSession/
MCPServer. Префиксы E5 сверены с [документацией Sentence Transformers](https://www.sbert.net/examples/sentence_transformer/applications/computing-embeddings/README.html).
stdio использует настоящий протокол SDK; [описание транспорта](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports).

Не включать публикацию, push и загрузку на внешний диск в локальную приёмку.
