# Как правильно продемонстрировать день 31

Основная версия — примерно 55 секунд, с русской озвучкой QwenTTS Voice Design.
Один вопрос, один реальный ответ, три доказательства выполнения задания.
Выбор локальной или облачной LLM не является требованием задания.

## Короткий сценарий

| Примерное время | Что видно | Что объясняет голос |
|---|---|---|
| 0–7 с | Название и три требования | Помощник понимает конкретный проект |
| 7–18 с | Реальная форма /help и состав индекса | README и docs подключены; задаём вопрос о структуре и ветке |
| 18–28 с | Раскрытый фрагмент docs/architecture.md | Поиск нашёл документ с расположением компонентов |
| 28–39 с | Короткий ответ Gemini со ссылками | Ответ составлен по документам, его можно проверить |
| 39–55 с | Настоящий вызов MCP, branch=main и HEAD | Ветка получена из Git через MCP; все три требования показаны |

Тексты озвучки: narration.json. Генерация: generate_narration.py через API
установленного ComfyUI. Синтезируется описанный голос, голос человека не клонируется.
Каждая сцена длится по фактической длине своего аудио, поэтому речь и картинка
совпадают. Кадры — реальные снимки браузера, ожидание ответа сокращено и подписано.
Подробные JSON-каталоги, тесты, вторые вопросы и запуск моделей в короткую версию
не включаются. Их доказательства остаются в коде/evidence.

## Повторить запись

В одном терминале запустить server.py с DAY31_LLM_PROVIDER=gemini,
DAY31_LLM_MODEL=gemini-3.5-flash-lite и ключом в окружении. ComfyUI с установленным
ComfyUI-QwenTTS должен работать на loopback; модели VoiceDesign и локальный
Whisper уже должны быть скачаны. Затем из корня проекта:

```powershell
$env:DAY31_SHORT_DEMO = '1'
$env:DAY31_DEMO_URL = 'http://127.0.0.1:8796/'
node day31-developer-assistant\capture-demo.mjs
.\.venv\Scripts\python.exe day31-developer-assistant\generate_narration.py --submit --url http://127.0.0.1:8188
.\.venv\Scripts\python.exe day31-developer-assistant\record_short_video.py
```

Для проверки произнесённого текста: verify_narration.py запускать Python из
ComfyUI, где установлен Whisper; --whisper-model указывает локальный .pt.
Рабочий ролик: ChallengeVideos/day31-demo-voiced.mp4, 54.70 с, 1920×1080,
H.264 + AAC. Первое длинное видео сохранено отдельно и больше не основное.
Изменённые cloud-адаптеры и прежний RAG проверены 39 тестами; реальный CLI-прогон
Gemini выполнил все 10 проверок. Сценарий не заявляет сравнение моделей.

## Подробная версия для самостоятельной демонстрации

Перед записью: построить индекс, настроить выбранный API и UI, выполнить тесты.
Не показывать загрузку модели минутами.

| Время | Действие | Что сказать / показать |
|---|---|---|
| 0:00–0:15 | Цель и схема | «Помощник отвечает о моём проекте. Документы — RAG, текущая ветка — MCP» |
| 0:15–0:35 | Открыть корпус | Корневой README, `docs/architecture.md`, API и схема данных; число документов/чанков в UI |
| 0:35–1:05 | `/help Как устроен проект и где находятся RAG и MCP?` | Настоящий ответ модели; конкретные папки, источники [n], раскрыть найденный фрагмент |
| 1:05–1:25 | Раскрыть MCP | `initialize`, `tools/list`, `get_project_context({})`, JSON ветки и SHA; сопоставить с Git |
| 1:25–1:55 | `/help Как проходит запрос /help и какие поля возвращает API?` | Ответ использует docs/api.md, показать источники и время генерации |
| 1:55–2:15 | `/help Какова выручка проекта за 2025 год?` | В документации нет выручки; показать честный отказ |
| 2:15–2:35 | Результаты | Тесты, реальные ответы, ограничения модели; код и видео готовы |

Не выдавать карточки с заранее написанными ответами за живой чат. Автоматическая
запись делает реальные запросы через UI; ожидание можно сокращать **с подписью**.
Не утверждать, что ссылки доказывают смысловую правильность: проверить ответы
вручную по фрагментам. На видео важен результат retrieval, а не только красивый текст.

Дополнительно, без включения в короткое видео: изменить документ → запрос должен
попросить `--index`; выполнить reindex. Для проверки смены ветки пользоваться
временным тестовым репозиторием, не переключать рабочую ветку с чужими изменениями.
