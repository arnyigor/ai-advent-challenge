# План реализации — День 15

## Цель

Создать ассистента с контролируемым жизненным циклом задачи: реализация невозможна до утверждения плана, завершение невозможно без успешной валидации, пауза сохраняет весь контекст, а модель не может напрямую менять состояние.

## Жизненный цикл

```text
planning --submit_plan--> plan_review
plan_review --approve_plan--> implementation
plan_review --reject_plan--> planning
implementation --submit_result--> validation
validation --fail_validation--> implementation
validation --approve_validation--> completed
```

`pause` не меняет этап, а блокирует переходы. `resume` восстанавливает тот же этап и ожидаемые действия.

## Этапы реализации

1. Зафиксировать декларативный контракт в `lifecycle.json`.
2. Реализовать доменную модель, `TransitionGuard` и переходы.
3. Добавить SQLite-хранилище, версии, артефакты и журнал всех попыток.
4. Добавить фасад ассистента с аргументированным отказом и следующим допустимым действием.
5. Сравнивать DeepSeek V4 Flash и Qwen3.8-27B через RouterAI на одном снимке без изменения состояния.
6. Добавить HTTP API и веб-интерфейс с диаграммой этапов, артефактами и журналом.
7. Покрыть позитивный путь, неправильные переходы, возвраты, паузу, восстановление и модели тестами.
8. Подготовить README, сценарий и автоматическую запись видео.
9. Запустить py_compile, pytest, node --check, сервер с дефолтными аргументами и запись видео.

## Критерии готовности

- Нельзя начать реализацию до `approve_plan`.
- Нельзя перейти в `completed` без `approve_validation` и отчёта проверки.
- Любой отказ оставляет состояние, версию и артефакты без изменений.
- Отказ записывается в аудит и сообщает допустимые действия.
- Во время паузы переходы запрещены.
- После перезапуска достаточно `task_id` для продолжения.
- Ответы моделей не могут обойти `TransitionGuard`.
- Готово проверяемое MP4-видео с основными сценариями.
