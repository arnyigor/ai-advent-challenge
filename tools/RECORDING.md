# Как записать демо-видео

Видео записывается скриптом **`record-video.mjs`** — без puppeteer/playwright,
чистым Node.js 22+ (встроенный `WebSocket`) + Chrome в headless-режиме + ffmpeg.

> Скрипт лежит в `day01-first-api-request/llm-demo/` — все команды ниже выполнять
> из этой папки (там же `run.bat`, `server.mjs`, `video/`).

## Что нужно

| Компонент | Зачем | Где искать |
|---|---|---|
| Node.js 22+ | скрипт (встроенный `WebSocket`); сервер работает на 18+ | `node -v` |
| Google Chrome | headless-браузер, управляется по CDP | стандартный путь установки; переопределить через `CHROME_PATH` |
| ffmpeg | сборка кадров в mp4 | `ffmpeg` в PATH; свой путь задать через `FFMPEG_PATH` |
| Запущенный сервер | `run.bat` → http://localhost:3000 | — |

Пути к Chrome/ffmpeg не хардкодированы под конкретную машину: скрипт читает
переменные окружения `CHROME_PATH` и `FFMPEG_PATH` (для ffmpeg достаточно
положить его в PATH).

## Запись

```bash
# 1) сервер должен работать: run.bat (http://localhost:3000)
node record-video.mjs                        # всё, что доступно → video/llm-demo.mp4
node record-video.mjs --out video/x.mp4      # свой путь
node record-video.mjs --backends mock,llama.cpp   # только выбранные бэкенды
```

Скрипт сам:
1. запускает headless Chrome (`--remote-debugging-port=9224`);
2. открывает http://localhost:3000 и ждёт детекта бэкендов (до 30 с — Gemini медленный);
3. включает «камеру» — снимает кадр каждые 125 мс (8 fps) в `video/frames/`;
4. по очереди для каждого доступного бэкенда:
   - кликает чип бэкенда;
   - **печатает промпт посимвольно** (55 мс/символ — видно, как «печатают»);
   - отправляет форму и ждёт появления `.meta` в **новом** сообщении (стриминг завершён) или ошибки;
   - держит готовый ответ 2.5 с.

Параллельно работает **фоновый скроллер**: каждые 300 мс прижимает `#chat` к низу
(`scrollTop = scrollHeight`), чтобы длинные ответы не уходили за вьюпорт.
5. собирает кадры в mp4 через ffmpeg (H.264, yuv420p, масштаб до чётных размеров).

Промпты для каждого бэкенда — в `SCENARIO` в начале скрипта (можно менять).

## Как это устроено (CDP без библиотек)

- Chrome стартует с флагом `--remote-debugging-port=9224`;
- `GET http://127.0.0.1:9224/json` → список вкладок → `webSocketDebuggerUrl`;
- дальше — обычный WebSocket и JSON-сообщения CDP:
  - `Page.navigate` — открыть страницу;
  - `Runtime.evaluate` — клики, печать, чтение DOM (вместо puppeteer);
  - `Page.captureScreenshot` — кадр PNG;
- «Печать» — посимвольное добавление символов в `#prompt.value` (55 мс/символ).

## Частые проблемы

| Симптом | Причина / решение |
|---|---|
| «Бэкенды не загрузились» | сервер не запущен или детект дольше 30 с — поднять сервер, повторить |
| «Нет доступных бэкендов для записи» | ни один чип не активен — проверить `curl localhost:3000/api/backends` |
| Порт 9224 занят | старый headless Chrome не умер — убить процесс chrome с этим портом |
| ffmpeg: «width not divisible by 2» | уже обработано фильтром `scale=trunc(iw/2)*2:...` в скрипте |
| Ответ бэкенда «на таймауте» | модель долго думает — увеличить цикл ожидания в `record-video.mjs`: `for (let i = 0; i < 120; i++) { await sleep(500); }` (120 × 500 мс = 60 с) |
| Последний ответ уходит за кадр вниз | `#chat` должен быть фиксированным скролл-контейнером: `body{height:100vh;overflow:hidden}` + `main{min-height:0}`. Тогда скроллер крутит именно `#chat`, а не страницу — иначе длинный ответ (mock/gemini) оказывается ниже вьюпорта и не попадает в кадр |
