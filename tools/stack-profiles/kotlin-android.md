# Стек-профиль: Kotlin / Android (Cicerone + Moxy + Room/Flow)

## Известные ловушки

- **Двойная инстанциация экрана через `router.newRootScreen`.** Вызов без проверки, что
  текущий корневой экран уже тот же самый, создаёт вторую копию (например,
  `MainScreenFragment`) — вторая копия молча не получает состояние первой, фичи вроде
  тултип-туров перестают срабатывать без явной ошибки.
- **`view?.post { ... }` на фрагменте, у которого `view` уже `null` или ещё не создан**
  (viewless-фрагмент) — колбэк молча не выполняется, никакого исключения.
- **`StateFlow` для одноразовых команд/навигационных событий.** `StateFlow` реплеит
  последнее значение новым подписчикам — при пересоздании View/фрагмента событие
  срабатывает повторно. Для одноразовых команд — `MutableSharedFlow` с `replay = 0`,
  `StateFlow` — только для состояния, которое действительно должно переживать пересоздание.
- **`backTo(null)`** уничтожает состояние адаптера/бэкстека — не автоматическая
  замена `newRootScreen`, даже если выглядит логичнее для конкретного перехода.
- **`take()`/`first()` на Flow-канале с одноразовыми командами** — деструктивное чтение:
  событие потребляется из канала, даже если обработчик не смог его применить (например,
  VM ещё не готова). Нужен паттерн peek/consume (посмотреть — обработать — только потом
  снять с канала), а не голый `take`.
- **Гонка между синхронной и асинхронной веткой инициализации состояния экрана.**
  Если состояние-флаг готовности (например, `screenContentReady = true`) выставляется
  только в асинхронной ветке — синхронный путь инициализации может о нём забыть,
  и код, ждущий этот флаг, зависает или срабатывает раньше времени.
- **Неполный набор веток `when` для типов entry-point/карточек экрана**, особенно если
  есть `else`-заглушка — компилятор не подскажет, что забыт конкретный кейс
  (например, отдельный `CARD_*`-тип), потому что `when` формально exhaustive за счёт `else`.

## Проверка

- Собрать модуль (например, `./gradlew compileDebugKotlin` или актуальный таск сборки проекта —
  подставь реальную команду вашего Gradle-конфига).
- Если настроен статический анализ (detekt/ktlint) — прогнать его.
- Для `when` по sealed class/enum — по возможности убирать `else`-заглушку, чтобы компилятор
  сам требовал обработки нового варианта при его добавлении.
