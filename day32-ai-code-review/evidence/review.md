### Потенциальные баги

#### P1: Расчет отрицательной цены и отсутствие валидации входных данных
* **Файл:** `pricing.py`
* **Строка:** 2
* **Сценарий сбоя:**
  1. Вызывающий код (например, `checkout.py` [R3]) передаёт значение скидки в процентах от 0 до 100 (например, `percent = 20` для скидки 20%).
  2. Из-за удаления деления на 100 формула `price * (1 - percent)` возвращает `100 * (1 - 20) = -1900`. Цена и итоговая сумма становятся отрицательными, что нарушает базовые правила расчета [R1].
  3. Из-за удаления проверки `if not 0 <= percent <= 100` передача отрицательных значений или значений больше 100 (при попытке передать долю `1.5` или процент `150`) не приводит к вызову `ValueError`, а возвращает некорректную (в том числе отрицательную) цену.
* **Исправление:**
  ```python
  def discount(price, percent):
      if not 0 <= percent <= 100:
          raise ValueError("invalid percent")
      return price * (1 - percent / 100)
  ```

### Архитектурные проблемы

1. **Нарушение архитектурного контракта модуля `pricing` [R1]:**
   Документация явно указывает, что процент скидки измеряется от 0 до 100, цены/итоги не должны становиться отрицательными, а вся валидация входит в зону ответственности `pricing` [R1]. Удаление валидации перекладывает ответственность за корректность данных на вызывающий код (`checkout.py` [R3]), что разрушает установленные границы модулей и контракт взаимодействия.
