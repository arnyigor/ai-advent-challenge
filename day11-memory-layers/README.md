# День 11. Модель памяти агента

**Видео-демо:** [day11-demo.mp4 на Яндекс.Диске](https://yadi.sk/i/atWrp7Nxu9xBEQ). Подписи расположены сверху. На одном вопросе показаны восемь вариантов памяти, затем тот же вопрос и одинаковый контекст передаются DeepSeek V4 Flash и Wormsoft GPT-OSS 20B. Их реальные ответы стоят рядом в конце ролика. Сценарий сверяет состав запросов и факты в ответах перед сохранением видео. Локальный MP4 исключён из git, как и видео предыдущих дней.

Агент с тремя явно разделёнными слоями памяти. Каждый слой хранится в своём SQLite-файле в локальной папке `data/` (она не попадает в git):

| Слой | Файл | Область действия | Что сохраняется |
| --- | --- | --- | --- |
| Краткосрочная | `short.db` | пользователь + сессия | Реплики успешного диалога; явно сохранённые заметки |
| Рабочая | `working.db` | пользователь + задача | Факты и решения текущей задачи |
| Долговременная | `long.db` | пользователь | Профиль, предпочтения, устойчивые знания |

**Политика записи:** пользователь выбирает слой для каждого факта через форму «Сохранить факт» или CLI-команду `/save <слой> <ключ> = <значение>`. Автоматического извлечения и переноса фактов между слоями нет. Только пара успешных реплик `user/assistant` автоматически добавляется в краткосрочный transcript; при ошибке провайдера запись не происходит.

**Политика чтения:** в запрос модели входят выбранные слои: последние 6 реплик и заметки текущей сессии, факты активной задачи, долговременные факты пользователя. Интерфейс показывает точный состав запроса. Слои можно временно отключить для сравнения ответов, не удаляя данные из хранилища.

## Запуск

Нужен ключ выбранного провайдера: `DEEPSEEK_API_KEY`, `GEMINI_API_KEY` или `WORMSOFT_API_KEY`. Для повторной записи ролика нужны ключи DeepSeek и Wormsoft. Адрес Wormsoft берётся из `WORMSOFT_BASE_URL`, если он задан; иначе используется проверенный локальным прогоном адрес из `providers.py`. Ключи не хранятся в проекте и не отправляются браузеру.

```powershell
cd day11-memory-layers
pip install -r requirements.txt
python web_server.py          # адрес и свободный порт выводятся при запуске
python day11_agent.py         # CLI
python run_evaluation.py      # живое A/B сравнение, расходует API-токены
python run_evaluation.py --provider wormsoft --out results/evaluation-wormsoft.json
node record-video.mjs         # браузерное видео с реальными ответами
```

## Как оценивать

1. Записать `кодовое_слово = Кедр-71` в краткосрочную память, `срок = 15 декабря` в рабочую, `стиль_ответа = кратко, одним предложением` в долговременную. Убедиться в панели и в трёх файлах, что каждый факт находится только в выбранном слое.
2. Задать один вопрос о всех трёх фактах с включённой памятью и с отключённой. Сравнить ответы и содержимое `context` — это фактический запрос к модели.
3. Сменить сессию: диалог и краткосрочная заметка исчезнут из видимого контекста. Сменить задачу: рабочий срок исчезнет. Профиль пользователя остаётся в обоих случаях; другой пользователь его не получает.

В [`results/evaluation.json`](results/evaluation.json) сохранён реальный прогон 14 сентября 2026 года на `deepseek-v4-flash`: без памяти модель не назвала кодовое слово и срок, со всеми тремя слоями назвала `Кедр-71`, `15 декабря` и краткий стиль. Все пять автоматических проверок ответа и четыре проверки изоляции прошли. Формулировка ответа LLM может меняться; структурные проверки хранилища и переданного контекста выполняются отдельно от неё.

Второй прогон — [`results/evaluation-wormsoft.json`](results/evaluation-wormsoft.json) на `openai/gpt-oss:20b` через Wormsoft. Обе модели получили одинаковые системную инструкцию и сообщения при одинаковых выбранных слоях и прошли те же 5 проверок ответа и 4 проверки изоляции. Они по-разному формулируют ответы; при отсутствии памяти могут предполагать неподтверждённый стиль ответа. Это ограничение поведения модели, а не различие в маршрутизации памяти.

```powershell
python -m py_compile memory_store.py agent.py providers.py day11_agent.py web_server.py run_evaluation.py
python -m pytest ../tests/test_day11_memory_layers.py -q
node --check web/app.js
node --check record-video.mjs
```

## Артефакты

- `memory_store.py` — три файла и явная маршрутизация записи.
- `agent.py` — сборка контекста, выбор слоёв, запрос к модели и запись диалога после успеха.
- `providers.py` — адаптер к существующему `tools/llm`.
- `web_server.py`, `web/`, `day11_agent.py` — веб-интерфейс и CLI.
- `run_evaluation.py` — воспроизводимое живое сравнение и проверка границ.
- `record-video.mjs` — запись браузерного демо в `ChallengeVideos/day11-demo.mp4`.

Веб-сервер предназначен для локального запуска на `127.0.0.1`: идентификаторы пользователя, задачи и сессии демонстрационные, механизм авторизации здесь не реализован.
