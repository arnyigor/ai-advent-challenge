# Результаты оптимизации, 2026-10-08

## Выбранная конфигурация

Qwen3-1.7B Q4_K_M, CPU/8 потоков, temperature=0, max_tokens=1024, окно 4096, reasoning off, исходный system prompt дня 28. Сохранена в optimized.json, используется ask.py и run-cpu-model.bat. Достигнуто изменение памяти и повторяемости текста; улучшения качества и скорости не заявляются.

| Параметр / метрика | До | После |
|---|---:|---:|
| Temperature | 0,1 | 0 |
| Max tokens | 4096 | 1024 |
| Окно сервера | 8192 | 4096 |
| Вызовы, 6 вопросов × 3 повтора | 18 | 18 |
| Непустые / обрезаны | 18 / 0 | 18 / 0 |
| Медиана полного HTTP запроса, с | 8,63 | 11,27 |
| Sampled peak RSS процесса, MiB | 4024 | 3576 |
| Условная оценка качества, 0–2 | 0,67 | 0,67 |

До: baseline из temperature-confirmation-Q4_K_M.json. После: compact-confirmation-Q4_K_M.json. Измеренное снижение RSS — **11,13%**, около 448 MiB. Это разные запуски сервера, необходимые для изменения окна; измерения не доказывают универсальный процент экономии или выигрыш скорости. Медиана после выше: ускорение не получено. Окно, лимит и temperature изменены совместно: сравниваются конфигурации, а не изолированные эффекты каждого фактора. Источники и system prompt одинаковы; cache_n=0. Необрезанные ответы compact совпали дословно с temperature=0 при окне 8192; оценки перенесены только при совпадении всех трёх хешей answer/context/system.

При temperature=0 в каждом из шести вопросов получен один текст за три повтора. При 0,1 RSS и MCP дали по три разных текста; остальные по одному. Это наблюдение на наборе, не гарантия детерминизма. Максимум prompt_tokens 2091 + резерв 1024 = 3115, максимум completion_tokens — 181. Окно 4096 не обрезало контекст в этих тестах; --no-context-shift исключает сдвигание при дальнейшей генерации. Произвольные новые входы могут не поместиться.

## Температура и system prompt

Контроль температуры проведён в одном сервере: baseline/temperature, шесть вопросов × три повтора, одинаковые system prompt, max_tokens=4096 и окно 8192. Качество одинаковое 0,67, медианы 8,63 / 11,15 с. Снижение температуры не исправило смысловые ошибки и не ускорило ответы; выбрано для повторяемости текста.

Короткий русский шаблон ошибочно объявлял подтверждение оператора ненужным. Английский пропускал условия и неправильно нумеровал ссылки. Цитатный шаблон повторял образец в завершённых ответах; следующий MCP-вызов остановлен после более 1000 сгенерированных токенов по журналу, завершённый ответ не получен. Четыре завершённых вызова сохранены с aborted=true; это не полное сравнение.

Подробный CPU_FOCUSED проверен по три раза рядом с baseline при одинаковых 0,1/4096/8192. Средняя условная оценка выросла с 0,67 до 1,00, но на вопросе без данных в двух из трёх повторов модель после отказа приписала Atlas инструменты другой подсистемы. Медиана выросла с 9,74 до 30,06 с. **Отклонён по регрессии отказа**, несмотря на более высокое среднее. focused-safe сохранил однострочный отказ, но пропустил обязательное подтверждение оператора и отказался исправить ложную предпосылку; также отклонён.

Исправлена первичная оценка focused-пилота: корректный первый отказ заслонил следующие неподтверждённые факты о якобы инструментах Atlas. Балл вопроса 6 исправлен с 2 на 0, среднее с 1,17 на 0,83. Исходный отзыв сохранён в evidence/focused-pilot-Q4_K_M-initial-reviews.json; ответы не менялись. Оценки агентом не являются независимой экспертизой.

Reasoning on с бюджетом 512 на двух вопросах: MCP — частично улучшен маршрут, но неверно объяснены условия исключений (1/2, 128,33 с); ложная предпосылка Atlas исправлена (2/2, 69,45 с). Это отдельный скрининг, не полный прогон; режим не выбран по умолчанию из-за оставшихся ошибок и высокой задержки. completion_tokens в нём включает рассуждение и видимый ответ.

Сложные MCP/RSS-вопросы, неправильные ссылки и необоснованные отказы остаются ограничением маленькой модели. Шесть вопросов использовались для настройки и проверки; независимого holdout нет. Ресурсная оптимизация не означает улучшение фактической точности.

## Код и проверки

153 завершённых измеряемых вызова в 12 отчётах + 12 прогревов; отдельно один остановленный незавершённый вызов. ask.py дополнительно проверен реальным запросом через выбранный CPU-сервер: контекст совпал SHA-256 с frozen.json, ответ непустой, finish_reason=stop. Результат — results/ask-smoke.json. Все собственные процессы остановлены; Strata не вызывалась и не перезапускалась.

19 тестов дней 28/29 прошли, синтаксис Python проверен. Они проверяют HTTP-контракт, checkpoints, хеши, HTML escaping, передачу сохранённого prompt и отсутствие переопределения адресом Strata; не качество модели. Полные JSON/отзывы/контекст — evidence/, журналы и HTML — results/. Ниже первоначальный квантовый пилот с исправленными оценками.

## Первоначальный CPU-пилот

Qwen3-1.7B, один набор шести сложных RAG-вопросов дня 28, одинаковый сохранённый контекст. Три квантования из unsloth/Qwen3-1.7B-GGUF, ревизия d7f544eead698dbd1f15126ef60b45a1e1933222. SHA-256 всех весов совпал с метаданными источника. Q4_K_M уже был на диске; Q2_K и Q8_0 скачаны в G:/AIModels/SmallAgents/Qwen3-1.7B. Веса вне Git.

Собственный llama-server: 127.0.0.1:8081, CPU (--device none, --gpu-layers 0, --no-kv-offload, --no-op-offload), 8 потоков, 1 слот, окно 8192, reasoning off, --no-cache-prompt. Три baseline-прогона отличаются только весами; четвёртый меняет одновременно system prompt, temperature и max_tokens. По одному повтору; результаты диагностические. Сначала Q2_K, затем Q4_K_M, Q8_0, затем Q4_K_M с cpu-focused. Влияние порядка/нагрузки и файлового кеша не устранено.

MB — десятичный размер файла; MiB — RSS процесса. RSS снимался раз в 250 мс после прогрева, включая интервалы между запросами; не абсолютный пик и не размер весов. CPU процесса в среднем около 791–794%, то есть примерно восемь загруженных логических ядер. Замеры GPU относятся к устройству целиком и включают чужую Strata, поэтому в таблицу CPU-модели не включены. Скорость HTTP не равна скорости декодирования; timings и usage сохранены при наличии.

Качество оценено Codex по каждому ответу и сохранённым фрагментам; это не независимая/слепая оценка. Отзывы привязаны к SHA-256 ответа и контекста, содержат объяснение по каждому вопросу. 0 — неверный ответ/необоснованный полный отказ; 1 — частично верно, ошибки/пропуски/неподтверждённые ссылки; 2 — все запрошенные факты и ссылки корректны. Среднее шести оценок нельзя переносить на произвольные вопросы.

## Что показал пилот

Q2_K отказался на всех шести вопросах. Для вопроса про отсутствующую выручку это правильно; для остальных источники содержат хотя бы часть ответа. Его маленькая память и короткая генерация не компенсируют потерю качества.

Q4_K_M и Q8_0 дали правильные Atlas-факты, но сослались на неподходящий фрагмент для восстановления соединения. Оба выдумали ограничение одинаковых имён MCP-инструментов и сделали неподтверждённый вывод о внешней отправке RSS из INSERT OR IGNORE. На ложной предпосылке Atlas оба полностью отказались. Q8_0 в этом пилоте не добавил качества, медиана оказалась выше; статистической гарантии превосходства Q4_K_M нет.

cpu-focused на Q4_K_M правильно ответил на все три части Atlas и дал ссылки [1]/[2]. Ответ на ложную предпосылку назвал правильный код и необходимость подтверждения, но затем противоречиво объяснил её. Для Git дал часть доступных сведений вместо полного отказа. Однако в MCP выдумал knowledge.save, в RSS ошибся со ссылками и добавил неподтверждённые утверждения. Более подробные ответы увеличили задержку. Снижение max_tokens с 4096 до 1024 само по себе не ускоряет короткий ответ: оба бюджета здесь завершались раньше лимита.

## План после первоначального пилота

Для следующего эксперимента взять Q4_K_M как рабочую отправную точку. Изолировать изменения: отдельно шаблон с 0.1/4096, отдельно temperature=0, отдельно бюджет. Уплотнить контекст для маленькой модели, сохранив достаточные доказательства и заново проверив retrieval; новый набор контекста сравнить отдельно от чистого эффекта prompt. Упростить формат ответа, не теряя факты. После выбора — три повтора baseline/кандидат в одном запуске.

В первоначальном пилоте окно было 8192. Последующий эксперимент окна 4096 и выбранная конфигурация описаны выше. Видео ещё не записано.
