# Непрерывное демо дня 34

Основное видео теперь записывается как процесс работы браузера, а не слайды
с результатами. Все кадры сохраняются по порядку с временными метками.
Никакие ответы модели, вызовы MCP или содержимое файлов не подменяются.

## Что видно

1. Пустая форма, ввод цели: найти реализацию и использования промокодов,
   объяснить работу и обновить CHANGELOG по коду.
2. Нажатие запуска, индикатор работы и ожидание модели.
3. Появление каждого шага. Раскрываются аргументы поиска, совпадения в разных
   файлах, прочитанный код с номерами строк и операция записи.
4. Финальный ответ и diff сохранённого CHANGELOG.
5. Нажатие сброса проекта для повторения.

Ввод, нажатия, раскрытие результатов и чтение показываются с обычной скоростью.
Только бездействующее ожидание модели после первых секунд ускоряется в 12 раз,
с явной подписью в верхней полосе. Кадры захватываются непрерывно; монтаж
не заменяет процесс статичными финальными состояниями.

## Повторить

```powershell
# Терминал 1: настроенный бесплатный Gemini либо локальный сервер модели
.\.venv\Scripts\python.exe day34-file-assistant\server.py
# Терминал 2: реальный модельный прогон и непрерывный захват
node day34-file-assistant\capture-live-demo.mjs
.\.venv\Scripts\python.exe day34-file-assistant\record_live_video.py
```

Chrome, Node 22+, ffmpeg/ffprobe в PATH. Результат:
`ChallengeVideos/day34-demo.mp4`, метаданные — `evidence/live-video.json`,
полная трасса реального прогона и порядок кадров — `evidence/live-browser.json`.
Исходные кадры — в `video-frames/live-*`. При ошибке модели запись не объявляется
успешной; сырые кадры сохраняются для диагностики. Перед началом скрипт сбрасывает
демо-проект, в конце показывает сброс в интерфейсе.

Предыдущий ролик со слайдами сохраняется как `day34-captioned-slides.mp4`.
Старые capture-demo.mjs и record_video.py оставлены для воспроизведения
предыдущей версии; для основного видео используйте команды выше.
