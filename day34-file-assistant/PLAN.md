# День 34 — Ассистент для работы с файлами проекта

План зафиксирован до реализации, 15 октября 2026.

## Задание и суть

AI-ассистент, который активно работает с файлами проекта, а не просто отвечает
текстом: читает, ищет по нескольким файлам, анализирует, создаёт и изменяет файлы.
Пользователь формулирует задачу на уровне цели («обнови changelog по коду»),
ассистент сам решает, какие файловые операции выполнить и в каком порядке.

Главное отличие от дня 31: там MCP-инструмент вызывался детерминированно сервером
на каждый вопрос. Здесь нужен агентный цикл: модель видит каталог инструментов,
выбирает шаг, получает результат через настоящий MCP, планирует следующий шаг.

Без VPS: генерация — бесплатный Gemini (инфраструктура tools/llm), резерв —
локальный OpenAI-совместимый сервер или OpenRouter :free (образец дня 31).
MCP, файлы, UI — локально.

## Архитектура

```
Браузер/CLI → FastAPI → AgentLoop → MCP stdio client → day34-files (отдельный процесс)
              LLM (Gemini/local) ←── JSON-шаги ──┘        → sandbox sample_project/
```

- Модель отвечает одним JSON-шагом: `{"action":"tool","name","arguments","thought"}`
  или `{"action":"final","answer"}`. Текстовый протокол работает с любой моделью
  и не требует function-calling API. Сервер валидирует JSON, исполняет вызов через
  реальный MCP-клиент (initialize/tools/list/tools/call, SDK mcp 2.2.0) и добавляет
  результат в историю. Лимит 12 шагов, таймаут MCP-вызова и сетевые таймауты провайдера.
- Каталог инструментов модель получает из настоящего `tools/list`, а не из строки
  в промпте: схемы и описания всегда совпадают с сервером.

## Контракты до кода

MCP-сервер `day34-files`, sandbox = DAY34_PROJECT_ROOT (по умолчанию sample_project/).
Общие гарантии: только относительные пути внутри корня; path traversal, симлинки
наружу, скрытые файлы, `.env*`, `*key*`, `*secret*`, бинарные и файлы > 200 КБ
отклоняются явной ошибкой; запись атомарна (tmp + replace).

- `list_files(path=".", pattern="**/*")` → относительные пути и размеры, ≤ 200 записей.
- `read_file(path, start_line=1, end_line=null)` → нумерованные строки, ≤ 400 строк.
- `search_files(query, file_glob="**/*", max_results=20)` → regex, совпадения
  `path:line` + строка контекста. Невалидный regex — ошибка.
- `write_file(path, content)` → создать/перезаписать; возвращает unified diff
  относительно прежнего содержимого, `created: bool`.
- `replace_in_file(path, old, new, count=1)` → точечная правка; ошибка, если
  `old` не найден или найден больше `count` раз; возвращает unified diff.
- `session_diff()` → объединённый unified diff всех изменений сессии относительно
  постоянного эталона baseline/; список изменённых файлов.

HTTP (FastAPI, порт DAY34_WEB_PORT=8834, loopback):

- `GET /api/bootstrap` → каталог MCP-инструментов, модель, список сценариев,
  статус baseline.
- `POST /api/runs` {goal} → {run_id}; цель 1..1000 символов; одна очередь,
  один активный прогон.
- `GET /api/runs/{id}` → статус, шаги (инструмент, аргументы, краткий результат,
  длительность), финальный ответ, session_diff, ошибка. UI опрашивает раз в секунду.
- `POST /api/reset` → восстановление sample_project/ из baseline/ (воспроизводимость
  демо; отклоняется, пока активен прогон).
- `GET /healthz` → живость MCP-процесса, без раскрытия ключей.

CLI: `agent.py --goal "..."` печатает JSON-трассу; `--reset` восстанавливает baseline.

## Демо-проект sample_project/

Мини-пакет «Прайсинг корзины» (Python), baseline/ рядом:

- `src/pricing.py` — PriceCalculator (скидки, налог), `src/promo.py` — промокоды
  (фича, не отражённая в CHANGELOG), `src/cart.py` и `src/api.py` — используют
  PriceCalculator, `src/report.py` — формирует отчёт.
- `tests/test_pricing.py`, `README.md` (намеренно устаревший раздел про API),
  `CHANGELOG.md` (есть Unreleased), `docs/adr-001.md`.

## Сценарии (минимум два — делаю три)

1. **Поиск использований (только чтение).** Цель: «Найди все места, где используется
   PriceCalculator, и объясни, где считается итоговая цена». Критерии: ≥ 2 вызовов
   инструментов, найдены pricing/cart/api, ответ со ссылками path:line, файлы не изменены.
2. **Обновление CHANGELOG (запись).** Цель: «В коде появились промокоды; обнови
   CHANGELOG.md в разделе Unreleased». Критерии: ассистент сначала ищет/читает код
   и changelog, затем replace_in_file/write_file; файл реально изменён; session_diff
   непустой и содержит promo.
3. **Проверка соответствия README (инвариант + правка).** Цель: «Проверь, что README
   соответствует коду, и исправь устаревшее». Критерии: найдено расхождение
   (в README устаревший пример/список), файл исправлен, diff показан.

## Модель и промпт

SYSTEM: ассистент разработчика, отвечает строго одним JSON-шагом; сначала читает,
потом пишет; перед записью показывает, что меняет; ссылки path:line; не выдумывать
файлы; при нехватке данных — честный отказ. Temperature 0.1, лимит выходных токенов.
История цикла: цель + шаги (thought, tool, args, сокращённый результат ≤ 4000 символов).

## Видео (по конвенциям дней 31–33)

Реальный headless Chrome (capture-demo.mjs), живой UI: цель → растущая трасса
шагов → ответ → diff. Монтаж реальных кадров с русской озвучкой QwenTTS через
ComfyUI (record_video.py, narration.json), ожидание сокращено и подписано.
Каждая сцена длится по факту аудио. Публикация на Яндекс.Диск вручную.
