# День 34. Ассистент для работы с файлами проекта

**Видео-демо:** [day34-demo.mp4 на Яндекс.Диске](https://yadi.sk/i/vHr4h0urmWHUGA) — 1:46, 1600×1000, H.264 25 fps; непрерывный захват реального
браузерного прогона: ввод цели → запуск → появление и раскрытие каждого
MCP-шага → чтение кода → сохранение CHANGELOG → diff → сброс проекта.
Только ожидание модели ускорено ×12 с явной подписью; операции и просмотр
результатов идут с обычной скоростью. Без озвучки. Предыдущий монтаж снимков
сохранён отдельно как `day34-captioned-slides.mp4`.

Ассистент **сам** работает с файлами, а не отвечает текстом: пользователь
ставит цель на уровне задачи, модель по каталогу `tools/list` решает, какие
инструменты вызывать, сервер исполняет вызовы через настоящий MCP stdio и
возвращает результаты. Без VPS: генерация — бесплатный Gemini, резерв —
локальный OpenAI-совместимый сервер или OpenRouter `:free`; MCP и файлы локально.

Подробный [аудит и анализ](AUDIT.md), [план](PLAN.md) и [сценарий записи](DEMO.md).

## Запуск из корня репозитория

```powershell
.\.venv\Scripts\python.exe -m pip install -r day34-file-assistant\requirements.txt
# GEMINI_API_KEY задаётся в окружении, не в коде и не на видео.
.\.venv\Scripts\python.exe day34-file-assistant\server.py
```

Откройте http://127.0.0.1:8834 (порт меняется через DAY34_WEB_PORT). В UI —
три готовых сценария, живая трасса шагов (инструмент, аргументы, результат),
финальный ответ, session_diff относительно постоянного baseline и кнопка сброса демо-проекта к эталону.

CLI: `agent.py --goal "обнови CHANGELOG по коду"` печатает JSON-трассу;
`--catalog` — каталог MCP-инструментов; `--reset` — восстановить проект.

Провайдеры: DAY34_LLM_PROVIDER = gemini (по умолчанию) | local | openrouter;
DAY34_LLM_MODEL, DAY34_MAX_TOKENS. Для local: LOCAL_LLM_URL и LOCAL_LLM_MODEL,
как в дне 31. OpenRouter принимает только openrouter/free или модели `:free`;
платного fallback нет, ошибки показываются честно.

## Архитектура

```
Браузер/CLI → FastAPI → агентный цикл → MCP stdio → day34-files → sample_project/
              Gemini/local ← JSON-шаги ┘              (sandbox + baseline)
```

- Модель на каждом шаге возвращает строго один JSON: `{"action":"tool",...}`
  или `{"action":"final","answer":...}`. Текстовый протокол работает с любой
  моделью, function-calling API не нужен. Лимит 12 шагов; ошибки инструментов
  и протокола возвращаются модели, она может исправиться (в записи видно, как
  модель забыла `path`, получила ошибку валидации MCP и повторила вызов верно).
- MCP-сервер `day34-files` (mcp 2.2.0): `list_files`, `read_file`,
  `search_files` (regex по корпусу), `write_file`, `replace_in_file` (точное
  число вхождений), `session_diff` (объединённый diff относительно baseline).
- Sandbox: только относительные пути внутри корня; path traversal, симлинки
  наружу, скрытые файлы, секреты по имени, бинарники и файлы > 200 КБ
  отклоняются явной ошибкой. Запись атомарна, окончания строк нормализуются
  в LF (иначе `write_text` на Windows раздувает diff переводом в CRLF).

## Сценарии

1. **Поиск использований** — «найди все места, где используется PriceCalculator»:
   только чтение, ответ со ссылками path:line, файлы не изменены.
2. **Обновление CHANGELOG по коду** — модель читает promo.py и CHANGELOG.md,
   добавляет запись в Unreleased; файл изменён, session_diff показывает правку.
3. **Проверка README на соответствие** — находит устаревший пример
   `calc.total(...)` и строку «Промокоды не поддерживаются», исправляет обе.

Демо-проект `sample_project/` — мини-пакет «Прайсинг корзины»; эталон в
`baseline/`, восстановление — кнопка в UI или `--reset` (воспроизводимость).

## Проверка и ограничения

```powershell
.\.venv\Scripts\python.exe -m pytest tests\test_day34_file_assistant.py -q   # 41 тест
.\.venv\Scripts\python.exe day34-file-assistant\verify.py                    # 3 сценария, реальная модель
```

41 unit/интеграционный тест: sandbox-защита, все шесть инструментов, парсер
шагов, восстановление после ошибок протокола, лимит шагов, неизвестный
инструмент, сквозной цикл через настоящий MCP stdio с подставной моделью,
веб-API. `verify.py` — три сценария с реальной Gemini, автоматические
критерии; отчёт — [evidence/acceptance.json](evidence/acceptance.json)
(результат последнего прогона хранится в JSON; статус проверяйте по all_passed).

Ограничения: семантическое качество правок не доказывается машинно — diff и
трассу смотрит человек; модель может не уложиться в 12 шагов (ошибка видна);
истории диалога между прогонами нет; детерминизм не гарантирован — про
воспроизводимость речь про сброс проекта и сохранённую трассу/evidence.

## Повторить видео

```powershell
.\.venv\Scripts\python.exe day34-file-assistant\server.py  # терминал 1
node day34-file-assistant\capture-live-demo.mjs            # терминал 2
.\.venv\Scripts\python.exe day34-file-assistant\record_live_video.py
```

Нужны Chrome, Node 22+, ffmpeg и ffprobe в PATH. Скрипт выполняет новый
запрос к реальной модели и снимает браузер непрерывно; не воспроизводит
заранее записанные ответы. Трасса и кадры: `evidence/live-browser.json`,
метаданные видео: `evidence/live-video.json`. Старые capture-demo.mjs,
record_video.py и generate_narration.py относятся к предыдущему монтажу.

## Локальная модель и бесплатный Gemini

Для полностью локальной генерации (сервер модели запустите отдельно):

```powershell
$env:DAY34_LLM_PROVIDER = 'local'
$env:LOCAL_LLM_URL = 'http://127.0.0.1:8085/v1'
$env:LOCAL_LLM_MODEL = 'имя-модели-из-v1-models'
.\.venv\Scripts\python.exe day34-file-assistant\server.py
```

Поддерживается OpenAI-совместимый chat/completions. Wormsoft отдельно не проверен;
если он предоставляет этот протокол, укажите его URL и имя модели здесь.
Для Gemini нужен ключ проекта **Free Tier без подключённого биллинга** и модель
с доступной бесплатной квотой. Тариф определяется проектом ключа, приложение
его не проверяет: [биллинг Google](https://ai.google.dev/gemini-api/docs/billing/).
Ограничение OpenRouter `:free` не распространяется на тариф Gemini.

`/healthz` проверяет наличие каталога проекта; `/api/bootstrap` действительно
подключается к MCP и получает tools/list. Итоговый diff вычисляется заново
после последнего действия модели. Для независимых сценариев выполняйте reset:
сравнение идёт с постоянным baseline. Сброс удаляет содержимое выделенного
демо-каталога; не указывайте в DAY34_PROJECT_ROOT рабочий репозиторий.
Полные трассы приёмки: `evidence/usage-trace.json`, `changelog-trace.json`,
`readme-check-trace.json` (создаются verify.py).

При ошибке генерации UI сохраняет трассу выполненных шагов и показывает diff уже
сохранённых правок: ошибка модели не означает, что файлы остались без изменений.


## Результат повторного аудита 15 октября

41 тест прошёл; JavaScript проверен через node --check, сканирование секретов
не обнаружило ключей. Повторная приёмка Gemini: поиск прошёл; обновление
CHANGELOG прервалось сетевой ошибкой после сохранения правки; проверка README
получила пустой ответ. Последний отчёт acceptance.json честно содержит
all_passed=false. Старый монтаж относится к предыдущему успешному прогону;
его браузерная трасса сохранена в evidence/browser-demo.json. Новый непрерывный
прогон записан отдельно в evidence/live-browser.json.
Текущая доступность облачной модели не гарантирована. После приёмки учебный
проект восстановлен к baseline. Локальный endpoint 127.0.0.1:8085 при аудите
не был запущен, поэтому реальная локальная генерация повторно не проверена.


Новый непрерывный прогон успешно завершён: search_files ×2 → read_file →
list_files → read_file → replace_in_file → session_diff → final.
Изменён CHANGELOG.md, затем в кадре выполнен сброс проекта.
Полная запись: 283 последовательных браузерных кадра, 106 секунд.
Это отдельный успешный прогон; он не меняет результаты старого пакетного
acceptance.json с сетевыми ошибками.

При сдаче полный набор `python -m pytest tests -q` прошёл: **498 тестов**,
одно предупреждение зависимости. Тестовые импорты дня 34 изолированы, чтобы
одноимённые модули предыдущих дней не конфликтовали в общем прогоне.
