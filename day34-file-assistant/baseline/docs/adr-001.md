# ADR-001: Суммы в копейках, а не float

## Статус

Принято, 2026-10-01.

## Контекст

Денежные расчёты во float дают ошибки округления (0.1 + 0.2 != 0.3).

## Решение

Все суммы храним в копейках (int). Налог и скидки округляем через round()
на каждом шаге. `PriceCalculator` — единственное место, где считается цена;
остальные модули обязаны использовать его, а не свою арифметику.

## Последствия

- При добавлении новых видов скидок (например, промокодов) правка идёт
  в pricing.py или в отдельный модуль, который вызывает PriceCalculator.
- Тесты проверяют точные значения в копейках.
