# День 25. Мини-чат с RAG + памятью задачи (production-like)

**Видео-демо:** [day25-demo.mp4 на Яндекс.Диске](https://yadi.sk/i/71na0i1B7uXv-Q) — реальный чат: ответ с источниками и цитатами, панель «Память задачи», разрешение местоимения «это» через состояние, append-only обновление памяти. Видео — монтаж реальных кадров интерфейса с пояснениями; ожидание модели сокращено, озвучки нет.

CLI/веб-чат, который хранит историю диалога, на каждый вопрос ищет контекст
в базе через RAG, отвечает по найденному и **всегда показывает источники**.
Поверх этого — память задачи: цель диалога, что пользователь уже уточнил,
зафиксированные ограничения и термины.

## Связь с Днями 22–24

Пайплайн Дней 22–24 не меняется и подключается отдельным именованным модулем:
`day25-rag-chat-memory/chat_agent.py` загружает
`day24-citations-grounding/rag_agent.py` (который сам загружает День 23).
Каждый ход чата проходит через полный validated RAG Дня 24: condense-запрос →
vector + FTS5 поиск → cosine threshold 0.83 → rerank (75% cosine + 25% lexical) →
топ-8 чанков из 16 кандидатов каждого канала → генерация с обязательными `answer/sources/quotes/claims` →
проверка дословности цитат и метаданных → смысловая проверка отдельным вызовом.
В вопросах о реализации PLAN.md исключается из кандидатов; при явном запросе о плане доступен. Проверка смысла оценивает утверждения ответа, а не поисковые синонимы; дословная цитата из индекса не требует второго независимого источника.
Индекс — `day21-document-indexing/data/indexes/structure.sqlite3`.

## Память задачи (task state)

Состояние хранится отдельно от истории чата:

| Поле | Что содержит |
|---|---|
| `goal` | исходная цель диалога; закрепляется кодом на всю сессию |
| `clarified` | что пользователь уже уточнил (факты, контексты) |
| `constraints` | зафиксированные ограничения («только стандартная библиотека») |
| `terms` | зафиксированные термины и идентификаторы (`INSERT OR IGNORE`) |

Инвариант **append-only проверяет код, а не модель**: модель предлагает новое
состояние отдельным вызовом, `merge_state()` сохраняет все ранее
зафиксированные пункты дословно и добавляет только действительно новое
(сравнение без учёта регистра). Некорректный ответ модели не портит состояние —
сохраняется предыдущая версия; проверенный ответ всё равно записывается. Цель не заменяется предложением модели. Для другой цели или отмены ограничения нужна новая сессия. Каждая запись имеет optimistic version и журнал
событий (`task_state.db`), история чата — `chat.db`. Оба файла записываются одной SQLite ATTACH-транзакцией (rollback journal): состояние, события и пара сообщений сохраняются вместе. Сессия возобновляется по
`session_id` после перезапуска.

На каждом ходу condense-rewrite превращает сообщение в самостоятельный
поисковый запрос с учётом истории и состояния: местоимения («это», «он»)
разрешаются в конкретные объекты. В генерацию передаются исходное сообщение, цель и ограничения; память не считается доказательством. К механизму добавляются поисковые синонимы
(как в Дне 24). Отказ («не знаю» + просьба уточнить) сохраняет пустые
sources/quotes: доказательства не выдумываются.

## Интерфейс

- **Веб** (`web_server.py` + `web/`): диалог слева (у каждого ответа — источники
  с source/section/chunk_id и дословные цитаты), «Память задачи» справа
  (цель, уточнения, ограничения, термины, версия состояния), новые и
  возобновляемые сессии.
- **CLI** (`cli.py`): тот же ChatAgent; команды `/state` и `/exit`.

## Проверка на двух длинных сценариях

`evaluate.py` прогоняет два сценария по 12 сообщений реальными вызовами
DeepSeek и пишет `results/scenarios.json`:

- **Сценарий A** — дедупликация в RSS-планировщике Дня 18: механизм, файл и
  SQL-конструкция, ограничения «только стандартная библиотека» и «схему базы
  не меняем», обоснование безопасности повторного сбора, итоговая сводка.
- **Сценарий B** — MCP: композиция Дня 19 против оркестрации Дня 20, передача
  данных между `search → summarize → saveToFile`, лимиты, ограничение «только
  бесплатные модели», off-topic-проба (цена акций) с корректным «не знаю» и
  возврат к теме, итоговый вывод.

На каждом ходу проверяется: статус совпал с ожиданием; у отвеченного хода есть
источники и цитаты; цитаты дословно входят в найденные чанки; метаданные
совпадают с индексом; состояние обновилось без ошибок; отказ — без
доказательств. В конце сценария: цель удержана (ключевые слова исходной цели
в финальном `goal`), все заявленные пользователем ограничения и термины
присутствуют в финальном состоянии.

Офлайн-тесты (fake-модель): `tests/test_day25_rag_chat_memory.py` — схема
состояния, append-only merge, optimistic version, хранилище чата и возобновление
сессии, подключение источников к ходу, отказ без источников, выживание состояния
при мусорном ответе модели, HTTP API.

## Запуск

Из корня репозитория:

```powershell
.\.venv\Scripts\python.exe -m pip install -r day25-rag-chat-memory\requirements.txt
.\.venv\Scripts\python.exe day25-rag-chat-memory\web_server.py   # веб-чат
.\.venv\Scripts\python.exe day25-rag-chat-memory\cli.py          # CLI-чат
.\.venv\Scripts\python.exe day25-rag-chat-memory\evaluate.py     # 2 сценария
```

Порт задаётся `DAY25_WEB_PORT`; модель — `DAY25_MODEL` (по умолчанию
`deepseek:deepseek-v4-flash`), контекст — `DAY25_TOP_K_AFTER` (по умолчанию 8).
Нужны построенный индекс Дня 21 и настроенный провайдер. Данные сессий — в
`day25-rag-chat-memory/data/` (исключены из Git).

## Понятное демо

Откройте URL сервера с `?demo=1`. Вверху есть восемь этапов с пояснениями и кнопка «Следующий этап». Покажите вопрос о RSS, откройте цитату, уточните «в каком файле это реализовано?», задайте ограничение «только стандартная библиотека» и запросите итог. У следующего ответа видны цель и ограничения, переданные модели. Создайте новую сессию и выберите старую в списке — история, источники и память восстановятся. После перезапуска сервера открывайте ссылку с `session=...` или выбирайте сессию.

Кнопка «Показать результаты 2 сценариев» читает сохранённый отчёт, а не запускает модель. Отчёт проверяет цель на каждом ходу, передачу памяти и предыдущих ограничений, цитаты и метаданные. Это структурная проверка и контроль примеров, не гарантия всех будущих ответов.

Для повторной сборки видео сохраните настоящие снимки UI и `video-frames/final/manifest.json`: массив объектов `{"file":"абсолютный путь к JPG","seconds":8}`. `record-video.mjs` собирает их в MP4. Данные сессий и кадры исключены из Git; результаты сценариев сохранены для проверки. Для сценариев нужен доступ к настроенной модели; офлайн-тесты ключей не требуют.

Ограничения: локальный сервер рассчитан на одного пользователя, одновременно обрабатывает один ход. Списки памяти ограничены 40 пунктами, сходные переформулировки могут накапливаться. При исчерпании лимита сохраняется предыдущая память и выводится предупреждение. Исходная RSS-система использует `requests` для загрузки RSS; ограничение сценария относится именно к механизму хранения и дедупликации (`sqlite3`).

## Итоговая проверка

Два реальных сценария по 12 сообщений: `dedup: passed`, `mcp: passed`. В RSS-сценарии на вопрос о SQL-конструкции допустимы оба подтверждённых механизма: `PRIMARY KEY` обеспечивает уникальность URL, `INSERT OR IGNORE` обрабатывает повторную вставку. Первоначальный критерий требовал только второй; сохранённые ответы перепроверены исправленным критерием, без новых вызовов модели. Исходный отчёт до исправления сохранён локально.

Повторить аудит сохранённых доказательств: `.\.venv\Scripts\python.exe day25-rag-chat-memory\evaluate.py --audit-report day25-rag-chat-memory\results\scenarios.json`. Аудит откажется, если тексты сообщений отличаются от сценариев. Цитаты, ответы и исходные результаты не изменяются.

Сценарий видео и таймкоды: [DEMO.md](DEMO.md). Видео — 1:59, 1920×1080, H.264; проверены кадры цитаты, памяти, отказа и итогового отчёта.

Финальные проверки: 370 тестов репозитория прошли, включая 26 тестов дня 25; JavaScript прошёл синтаксическую проверку. Сканирование файлов дня 25 не обнаружило секретов.
